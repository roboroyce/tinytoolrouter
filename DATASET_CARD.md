# DATASET_CARD.md — TinyToolRouter training & evaluation data (v2)

**Status:** the synthetic dataset is fully specified and its generator is
implemented (`src/gen_dataset.py`). It is **original content** authored by this
project, releasable under **Apache-2.0**. No external dataset has been
downloaded or used.

## 1. Splits (deterministic, seed 7)

Regenerate:

```bash
python3 src/gen_dataset.py --out data --seed 7 \
    --n-train 600 --n-seen 140 --n-unseen 60 --n-notool 40
```

| File | Rows | `family` | What it tests |
|---|---|---|---|
| `data/train.jsonl` | 600 | `train` | the 9 *seen* tools, train templates + train value pools |
| `data/test_seen.jsonl` | 131 | `seen_paraphrase` | **held-out** phrasing for the seen tools |
| `data/test_unseen.jsonl` | 60 | `unseen_schema` | tools **never seen in training** |
| `data/test_notool.jsonl` | 40 | `no_tool` | requests matching no tool → must abstain |
| `data/test.jsonl` | **231** | (concat of the three) | main harness input |
| `data/test_v1_original.jsonl` | 42 | `seen_paraphrase` | the pre-v2 split, kept for comparison |

Exact counts and sha256 per file are in `data/MANIFEST.json`.

## 2. Format

```json
{"id": "…16 hex…", "family": "unseen_schema", "held_out_tool": true,
 "messages": [
   {"role": "system", "content": "<router instructions incl. no_tool rule>"},
   {"role": "user",   "content": "{\"tools\": [<schema>, <distractor>, <distractor>], \"request\": \"…\"}"},
   {"role": "assistant", "content": "{\"name\": \"…\", \"arguments\": {…}}"}],
 "gold": {"name": "…", "arguments": {…}}}
```

Every user turn carries **valid JSON schemas** (checked by
`schema_utils.validate_schema`) plus two distractor tools, so the model learns
to read the schema rather than memorise a fixed list.

## 3. Tool registry

- **Seen (9):** `get_weather`, `send_email`, `create_calendar_event`,
  `search_web`, `convert_currency`, `set_timer`, `translate_text`,
  `filter_items`, `tag_note`.
- **Unseen (5, evaluation only):** `play_music`, `get_stock_price`,
  `book_restaurant`, `draw_chart`, `create_reminder`.

Argument types covered: `string`, `integer`, `number`, `boolean`,
`array<string>`, `array<number>`. Required and optional arguments both appear.

## 5. Leakage & hygiene controls (asserted by tests)

1. **Template disjointness** — train ∩ held-out templates = ∅; the
   seen-paraphrase and unseen-schema template sets are also disjoint.
2. **Value-pool disjointness** — held-out pools share no non-boolean value with
   the training pools.
3. **Tool disjointness** — `unseen_schema` tools never appear in training.
4. **Id disjointness** — id = sha256(request+gold)[:16]; train ∩ held-out = ∅;
   `MANIFEST.json` records `"leakage_check": "pass"` and `duplicate_ids: []`.
5. **Determinism** — same seed ⇒ byte-identical files (tested).
6. **Schema validity** — asserted for every registry entry.

Residual risk: the *system prompt* is shared across splits (it is the
instruction, not supervision). The held-out templates make prompt memorisation
an unlikely explanation for gains.

## 6. Limitations

- Synthetic v2: teaches routing discipline and schema reading, not broad world
  knowledge.
- English only; 14 tools total, no nested-object arguments yet.
- `test_seen` requested 140 rows but only **131 unique** combinations exist;
  the generator emits all uniques and warns rather than duplicating.
- Still worth adding ~100 hand-written, human-reviewed cases before a
  confident public claim; treated as future work.
